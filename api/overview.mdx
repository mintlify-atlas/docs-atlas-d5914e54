# VS Code Extension API Overview

The Visual Studio Code Extension API allows you to extend VS Code's functionality through a rich set of JavaScript/TypeScript APIs. This comprehensive API provides access to the editor's core features and enables you to create powerful extensions that integrate seamlessly with the VS Code experience.

## What is the VS Code Extension API?

The VS Code Extension API is a collection of JavaScript APIs that extensions can use to interact with VS Code. It provides programmatic access to:

- **Editor functionality**: Text editing, selections, decorations
- **Workspace management**: Files, folders, configuration
- **Language features**: IntelliSense, diagnostics, code actions
- **UI components**: Quick picks, input boxes, status bar, webviews
- **Debugging**: Debug adapters and debug UI
- **Source control**: SCM providers and git integration
- **Terminal**: Integrated terminal interaction
- **Extensions**: Interact with other extensions

## Main API Surface (vscode.d.ts)

The entire stable Extension API is defined in a single TypeScript definition file called `vscode.d.ts`. This file serves as the contract between VS Code and extensions, defining all available types, interfaces, classes, and namespaces.

### Key Characteristics

<AccordionGroup>
  <Accordion title="Single Module Design">
    All APIs are exported from the `vscode` module:
    
    ```typescript
    import * as vscode from 'vscode';
    
    // Access namespaces
    vscode.commands.executeCommand('...');
    vscode.window.showInformationMessage('...');
    
    // Use classes and interfaces
    const position = new vscode.Position(0, 0);
    const uri = vscode.Uri.file('/path/to/file');
    ```
  </Accordion>
  
  <Accordion title="Namespace Organization">
    The API is organized into logical namespaces:
    
    - `vscode.commands` - Command registration and execution
    - `vscode.window` - UI interactions and editor windows
    - `vscode.workspace` - Workspace and file system operations
    - `vscode.languages` - Language features and providers
    - `vscode.debug` - Debugging functionality
    - `vscode.scm` - Source control management
    - `vscode.tasks` - Task execution
    - `vscode.extensions` - Extension management
    - `vscode.env` - Environment information
    - `vscode.notebooks` - Notebook support
    - `vscode.chat` - Chat participant API
    - `vscode.lm` - Language model API
  </Accordion>
  
  <Accordion title="Type Safety">
    The API is fully typed using TypeScript, providing:
    
    - IntelliSense and autocomplete in supported editors
    - Compile-time type checking
    - Inline documentation
    - Better refactoring support
  </Accordion>
</AccordionGroup>

### Core API Components

The `vscode.d.ts` file includes:

1. **Interfaces**: Define contracts for objects (e.g., `TextDocument`, `Command`)
2. **Classes**: Concrete types you can instantiate (e.g., `Position`, `Range`, `Uri`)
3. **Enums**: Named constants (e.g., `TextEditorCursorStyle`, `ViewColumn`)
4. **Namespaces**: Organize related functionality (e.g., `commands`, `window`)
5. **Type Aliases**: Simplified type definitions (e.g., `Thenable<T>`, `ProviderResult<T>`)

## API Stability and Versioning

### Semantic Versioning

VS Code uses semantic versioning (semver) for API compatibility:

```json
{
  "engines": {
    "vscode": "^1.85.0"
  }
}
```

This declaration means:
- Your extension requires VS Code version 1.85.0 or higher
- The `^` symbol indicates compatibility with any 1.x version >= 1.85.0
- Breaking changes only occur in major versions (e.g., 2.0.0)

<Note>
In practice, VS Code has maintained backward compatibility across all 1.x releases, meaning extensions built for VS Code 1.0 still work in 1.85+.
</Note>

### API Evolution

The VS Code API evolves through a careful process:

<Steps>
  <Step title="Proposed API Phase">
    New APIs start as proposed APIs that are:
    - Not included in `vscode.d.ts`
    - Defined in separate `vscode.proposed.*.d.ts` files
    - Subject to breaking changes
    - Only available to extensions that opt-in
  </Step>
  
  <Step title="Finalization">
    After testing and refinement, APIs are:
    - Moved to stable `vscode.d.ts`
    - Guaranteed to remain stable
    - Available to all extensions
  </Step>
  
  <Step title="Deprecation (Rare)">
    When APIs need to change:
    - Old APIs are marked `@deprecated`
    - Better alternatives are provided
    - Deprecated APIs continue to work
  </Step>
</Steps>

## Proposed vs Stable APIs

### Stable APIs

The stable API surface is defined in `vscode.d.ts` and includes all production-ready functionality. These APIs:

- Are backward compatible
- Are fully documented
- Can be used in published extensions
- Have comprehensive test coverage

**Example from stable API:**

```typescript
import * as vscode from 'vscode';

export function activate(context: vscode.ExtensionContext) {
  // Register a command - stable API
  const disposable = vscode.commands.registerCommand(
    'myExtension.helloWorld',
    () => {
      vscode.window.showInformationMessage('Hello World!');
    }
  );
  
  context.subscriptions.push(disposable);
}
```

### Proposed APIs

Proposed APIs are experimental features under development. They:

- May change or be removed
- Require explicit enablement
- Cannot be published to the Marketplace
- Are intended for feedback and testing

To use proposed APIs, you must:

1. Enable them in `package.json`:
```json
{
  "enabledApiProposals": [
    "languageModelSystem",
    "chatParticipantAdditions"
  ]
}
```

2. Reference the type definitions:
```typescript
import * as vscode from 'vscode';
// Proposed APIs are merged into the vscode namespace
```

<Warning>
Extensions using proposed APIs cannot be published to the Visual Studio Marketplace. They are only suitable for internal use or local development.
</Warning>
