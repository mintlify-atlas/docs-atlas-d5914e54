VS Code's **extension system** enables third-party developers to add new features, languages, themes, and debuggers without modifying the core codebase. This architecture keeps VS Code fast, stable, and extensible.

## Architecture Overview

Extensions run in a separate **extension host process**, isolated from the main VS Code process for stability and security.

<Frame>
```
┌──────────────────────────────────────────────────┐
│         Main Process (Electron/Browser)          │
│                                                   │
│  ┌─────────────┐         ┌──────────────────┐   │
│  │  Workbench  │ ◄─────► │ Extension Host   │   │
│  │     UI      │  RPC    │   Process        │   │
│  └─────────────┘         └──────────────────┘   │
│                                   │               │
│                          ┌────────┴────────┐     │
│                          │                 │     │
│                     Extension 1       Extension 2 │
│                     (TypeScript)      (JavaScript)│
└──────────────────────────────────────────────────┘
```
</Frame>

<Steps>
  <Step title="Extension Discovery">
    VS Code discovers extensions in the extensions folder and reads their `package.json` manifests
  </Step>
  
  <Step title="Extension Activation">
    Extensions are activated lazily based on activation events (file opened, command invoked, etc.)
  </Step>
  
  <Step title="API Access">
    Extensions interact with VS Code through the `vscode` API module
  </Step>
  
  <Step title="Process Isolation">
    Extension code runs in a separate process, protecting VS Code from crashes
  </Step>
</Steps>

## Extension Host

The extension host is a separate Node.js (or Web Worker) process that executes extension code.

**Location:** `src/vs/workbench/services/extensions/`

<CodeGroup>
```typescript Extension Host Types
enum ExtensionHostKind {
  LocalProcess,     // Node.js process (desktop)
  LocalWebWorker,   // Web Worker (browser)
  Remote            // Remote server process
}
```


### Extension Host Communication

Extensions communicate with VS Code via JSON-RPC over IPC (Inter-Process Communication):

<CodeGroup>
```typescript Main Side (VS Code)
// In the main VS Code process
class MainThreadCommands {
  constructor(
    @ICommandService private commandService: ICommandService
  ) {}

  // Called by extension host
  $executeCommand(id: string, args: any[]): Promise<any> {
    return this.commandService.executeCommand(id, ...args);
  }
}
```

```typescript Extension Side
// In the extension host
class ExtHostCommands {
  // Call main thread
  async executeCommand(id: string, ...args: any[]): Promise<any> {
    return this.proxy.$executeCommand(id, args);
  }
  
  // Called by main thread
  $executeContributedCommand(id: string, args: any[]): Promise<any> {
    const handler = this.commands.get(id);
    return handler?.(...args);
  }
}
```
</CodeGroup>

### Extension Entry Point

Every extension has a main file that exports `activate` and `deactivate` functions:

<CodeGroup>
```typescript extension.ts
import * as vscode from 'vscode';

// Called when extension is activated
export function activate(context: vscode.ExtensionContext) {
  console.log('Extension activated');

  // Register a command
  const disposable = vscode.commands.registerCommand(
    'myExtension.helloWorld',
    () => {
      vscode.window.showInformationMessage('Hello from my extension!');
    }
  );

  // Add to subscriptions for cleanup
  context.subscriptions.push(disposable);

  // Access extension path
  console.log('Extension path:', context.extensionPath);
  
  // Use workspace storage
  context.workspaceState.update('lastRun', Date.now());
}

// Called when extension is deactivated
export function deactivate() {
  console.log('Extension deactivated');
}
```

```typescript ExtensionContext
interface ExtensionContext {
  // Paths
  readonly extensionPath: string;
  readonly extensionUri: Uri;
  readonly globalStorageUri: Uri;
  readonly logUri: Uri;
  readonly storageUri: Uri | undefined;
  
  // Storage
  readonly workspaceState: Memento;
  readonly globalState: Memento;
  readonly secrets: SecretStorage;
  
  // Lifecycle
  readonly subscriptions: { dispose(): any }[];
  
  // Extension info
  readonly extension: Extension<any>;
  readonly extensionMode: ExtensionMode;
}
```
</CodeGroup>

```typescript
const diagnosticCollection = vscode.languages.createDiagnosticCollection('myext');

function updateDiagnostics(document: vscode.TextDocument) {
  const diagnostics: vscode.Diagnostic[] = [];
  
  // Find issues
  const text = document.getText();
  const regex = /TODO/g;
  let match;
  
  while (match = regex.exec(text)) {
    const line = document.positionAt(match.index).line;
    const range = new vscode.Range(line, match.index, line, match.index + 4);
    
    diagnostics.push(new vscode.Diagnostic(
      range,
      'TODO found',
      vscode.DiagnosticSeverity.Warning
    ));
  }
  
  diagnosticCollection.set(document.uri, diagnostics);
}
```

```typescript
class MyTreeDataProvider implements vscode.TreeDataProvider<TreeItem> {
  private _onDidChangeTreeData = new vscode.EventEmitter<TreeItem | undefined>();
  readonly onDidChangeTreeData = this._onDidChangeTreeData.event;

    this._onDidChangeTreeData.fire(undefined);
  }

    return element;
  }

      // Root items

        new TreeItem('Item 1', vscode.TreeItemCollapsibleState.Collapsed),
        new TreeItem('Item 2', vscode.TreeItemCollapsibleState.None)

      new TreeItem('Child 1', vscode.TreeItemCollapsibleState.None),
      new TreeItem('Child 2', vscode.TreeItemCollapsibleState.None)
    ];
  }
}
```

## Extension Lifecycle

<Steps>
  <Step title="Discovery">
    VS Code scans extension directories on startup and reads `package.json` manifests
  </Step>
  
  <Step title="Registration">
    Extension contributions (commands, views, etc.) are registered without activating the extension
  </Step>
  
  <Step title="Activation">
    Extension is activated when an activation event occurs:
    ```typescript
    // Extension main file
    export function activate(context: vscode.ExtensionContext) {
      // Extension is now active
      console.log('Extension activated');
    }
    ```
  </Step>
  
  <Step title="Running">
    Extension responds to events, provides language features, executes commands
  </Step>
  
  <Step title="Deactivation">
    Extension is deactivated when VS Code closes or extension is disabled:
    ```typescript
    export function deactivate() {
      // Cleanup resources
      console.log('Extension deactivated');
    }
    ```
  </Step>
</Steps>

<Warning>
Extensions should activate quickly (< 1 second) to avoid degrading startup performance. Use lazy activation events whenever possible.
</Warning>

## Extension Best Practices

<CardGroup cols={2}>
  <Card title="Lazy Activation" icon="hourglass">
    Use specific activation events instead of `*`. Activate only when needed.
  </Card>
  
  <Card title="Dispose Resources" icon="trash">
    Add all disposables to `context.subscriptions` for automatic cleanup.
  </Card>
  
  <Card title="Use Async/Await" icon="clock">
    Most VS Code APIs are asynchronous. Use async/await for cleaner code.
  </Card>
  
  <Card title="Provide Telemetry" icon="chart-line">
    Track extension usage to understand user behavior (with user consent).
  </Card>
  
  <Card title="Handle Errors" icon="triangle-exclamation">
    Catch and handle errors gracefully. Show user-friendly error messages.
  </Card>
  
  <Card title="Respect Settings" icon="gear">
    Make features configurable and respect user settings.
  </Card>
  
  <Card title="Performance" icon="bolt">
    Avoid blocking the UI thread. Use workers for heavy computation.
  </Card>
  
  <Card title="Accessibility" icon="universal-access">
    Ensure UI is accessible with keyboard navigation and screen readers.
  </Card>
</CardGroup>
