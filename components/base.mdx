## Overview

The base layer (`src/vs/base/`) provides fundamental building blocks used throughout the VS Code codebase. It contains platform-agnostic utilities, data structures, and abstractions that form the foundation of the entire application.

## Architecture

The base layer is organized into three main categories:

- **common/** - Platform-agnostic utilities
- **browser/** - Browser-specific implementations
- **node/** - Node.js-specific implementations

### Key Principles

1. **No dependencies** on higher layers (platform, editor, workbench)
2. **Reusable** across different contexts
3. **Well-tested** fundamental implementations
4. **Performance-focused** core utilities

## Lifecycle Management {#lifecycle}

The lifecycle system manages resource cleanup and prevents memory leaks.

### IDisposable Interface

**Location:** `src/vs/base/common/lifecycle.ts:200`

```typescript
export interface IDisposable {
    dispose(): void;
}
```

### Disposable Class

Base class for disposable objects with tracking capabilities:

```typescript
import { Disposable } from 'vs/base/common/lifecycle';

class MyService extends Disposable {
    constructor() {
        super();
        
        // Auto-cleanup when disposed
        this._register(someResource);
    }
}
```

### DisposableStore

**Location:** `src/vs/base/common/lifecycle.ts:300`

Manages a collection of disposables:

```typescript
import { DisposableStore } from 'vs/base/common/lifecycle';

const disposables = new DisposableStore();

// Add disposables
disposables.add(subscription1);
disposables.add(subscription2);

// Dispose all at once
disposables.dispose();
```

<Accordion title="Lifecycle Patterns">

**Common Patterns:**

1. **Extending Disposable**
```typescript
class Widget extends Disposable {
    constructor() {
        super();
        this._register(this.onClose(() => this.cleanup()));
    }
}
```

2. **Using DisposableStore**
```typescript
class Manager {
    private disposables = new DisposableStore();
    
    init() {
        this.disposables.add(event.onDidChange(() => {...}));
    }
    
    dispose() {
        this.disposables.dispose();
    }
}
```

3. **toDisposable Helper**
```typescript
import { toDisposable } from 'vs/base/common/lifecycle';

const cleanup = toDisposable(() => {
    // Custom cleanup logic
});
```

</Accordion>

### Emitter Class

**Location:** `src/vs/base/common/event.ts:500`

Creates events that can be fired:

```typescript
import { Emitter, Event } from 'vs/base/common/event';

class DataModel {
    private _onDidChange = new Emitter<string>();
    readonly onDidChange: Event<string> = this._onDidChange.event;
    
    updateData(value: string) {
        this._onDidChange.fire(value);
    }
    
    dispose() {
        this._onDidChange.dispose();
    }
}
```

### Event Utilities

<Accordion title="Event Operators">

**Common Operators:**

```typescript
import { Event } from 'vs/base/common/event';

// Fire once then dispose
const onceEvent = Event.once(someEvent);

// Debounce events
const debouncedEvent = Event.debounce(someEvent, (last, e) => e, 100);

// Filter events
const filteredEvent = Event.filter(someEvent, e => e.value > 0);

// Map event values
const mappedEvent = Event.map(someEvent, e => e.toString());

// Combine multiple events
const anyEvent = Event.any(event1, event2, event3);
```

</Accordion>

### RunOnceScheduler

**Location:** `src/vs/base/common/async.ts:150`

Schedules work with automatic debouncing:

```typescript
import { RunOnceScheduler } from 'vs/base/common/async';

const scheduler = new RunOnceScheduler(() => {
    console.log('Executed once after 500ms');
}, 500);

// Multiple calls within 500ms result in single execution
scheduler.schedule();
scheduler.schedule();
scheduler.schedule();
```

## Best Practices

<Warning>
**Memory Management:** Always dispose resources! Use `DisposableStore` or extend `Disposable` to track cleanup.
</Warning>

<Tip>
**Event Usage:** Prefer `Event.once()` for one-time listeners to avoid memory leaks.
</Tip>

<Note>
**Async Patterns:** Use `RunOnceScheduler` for debouncing and `Throttler` for sequential async operations.
</Note>
